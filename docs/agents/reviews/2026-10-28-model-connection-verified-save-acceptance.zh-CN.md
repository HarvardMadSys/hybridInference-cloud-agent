# 个人模型连接：验证成功后保存与表单简化验收

日期：2026-10-28。对应 PR #1029，尚未合并或部署。

本记录更新此前的自动验证验收：最终产品删除了手动协议覆盖，以及先保存未验证连接再检查的流程。
此前记录中的手动高级模式、独立验证按钮和相应测试数属于历史版本。

## 最终行为

- 用户填写连接名称、Base URL、API key 和模型 ID；模型 ID 使用单行输入和可删除标签，最多 8 个。
- 唯一创建操作是「验证并保存」。每个模型自动检查原生 API，优先直连；只有 Chat Completions
  可用时，Codex 和 Claude Code 使用已经实现的成员私有兼容层。用户不选择协议，技术详情只读且默认折叠。
- POST/PATCH 在服务端验证后才写连接、密钥和验证事实。每个待验证模型至少有一种可用 Agent 路径
  才能整体保存；创建失败不留下连接或密钥，编辑失败保留原连接及正在使用的旧配置。
- 更换地址或密钥重新检查所有模型；添加模型先检查新增项；仅重命名、移除模型或相同值更新不发起
  服务商请求。发现模型后添加的入口也经过同一个验证提交边界。
- 失败时保留表单输入并给出逐模型的本地化原因；验证中禁止重复提交，取消按钮不会假装撤销服务端保存。
- 每个所有者每小时最多 20 个模型检查，整批一次性预留；最多并发检查 4 个模型，整次验证上限 240 秒。
  预算预留完成后才发起网络请求，不在数据库事务内等待服务商。
- 旧的手动 `protocols` 字段会被拒绝，没有通过直接调用 API 绕过验证的保存路径。数据库提交比较
  配置版本、凭据版本、模型列表及验证事实，防止验证期间删除、停用或移除再添加模型覆盖较新状态。

## 验收边界

- 浏览器预览使用实际构建的前端及隔离的内存模拟 API，运行在腾讯开发机，通过本机 SSH 转发访问。
  它不调用真实服务商、不保存真实密钥，也不创建真实任务。
- CLI 验证运行真实固定版本进程和兼容服务，但上游是隔离的 Chat 模拟服务；图片映射有单元测试，
  没有真实 CLI 图片回合验收。本轮没有真实服务商或 Kata 主机端到端验收。
- 检查只能证明当前地址、密钥和模型通过所测的流式工具回合，不能保证未来服务商可用性、模型质量
  或任意协议扩展。慢服务商可能触发 240 秒整批上限；不会为成功保存而跳过失败模型。
- 登录与 Agent 准入仍由 Gateway 提供；个人推理由用户服务商计费。本轮没有实现账号分离或公开网关。
- 功能开关仍默认关闭；启用前的主机、控制面升级及回退边界沿用模型连接设计。未执行部署或合并。
