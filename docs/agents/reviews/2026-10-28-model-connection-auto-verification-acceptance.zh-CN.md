## 产品行为

普通表单只要求名称、Base URL、API key 和模型 ID。保存本身不调用模型；“保存并验证”或模型旁的“验证”才发送有上限的小请求，并提示服务商可能计费。结果按模型保存，普通界面显示可用 Agent 和验证状态。协议声明改为高级选项，协议诊断默认折叠。

每个模型优先使用验证通过的原生接口；只有该模型通过 Chat Completions 验证时，Codex 和 Claude Code 才能使用已有私有转换服务。任务选择器与后端执行采用同一份模型能力规则，未验证模型不能因同连接中其他模型通过而获得执行权限。

## 审查修复

- 重命名及相同值的更新不再轮换凭据、终止常驻进程或清空验证。变更地址或密钥会失效对应验证；移除模型只清除其自身记录。
- Messages 工具结果中的图片，以及 Responses 的图片工具结果，保留图像数据，并在同一组工具回复完整结束后放入有效的 user 图像消息，避免静默变成占位符。
- 即时发送在数据库边界核对明确指定的模型与连接。不匹配时保留为排队消息；未指定模型仍表示继承当前回合。
- 验证结果记录同时核对连接、配置和凭据版本，不能恢复已停用或删除的连接；不同模型的并发结果不互相覆盖。主机核对 claim 与 residency 的协议路径，避免验证改变路径时使用旧启动方案。

- 验证的延迟返回不能覆盖刚编辑的连接、关闭未保存的编辑器或恢复已删除的连接；离开页面停止剩余批量验证。Codex 的 5 项受控异步回归先复现失败，修复后通过，包含编辑与验证响应处于同一 React 更新批次的情形。
- 保留并行提交 `19441325` 的共享下拉组件约束和其余下拉框测试；旧协议选择器已消失，其两项测试改为检查无协议菜单的逐模型验证、精确模型载荷、进行中禁用状态及桌面亮色／手机暗色布局。
