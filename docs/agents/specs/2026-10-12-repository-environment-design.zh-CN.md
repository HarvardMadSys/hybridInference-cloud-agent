## 1. 产品目标与完整交付范围

用户为一个仓库配置好依赖、变量、服务和常用命令，保存为一套云端环境。以后创建任务时选择它，平台自动准备工作区，准备成功后 agent 才开始工作。配置可以重复使用，每个新工作区仍有独立的容器和文件。

例如，一个 Web 项目的「开发环境」可以包含：

- 普通变量 `APP_ENV=development`，以及调用外部服务需要的 Secret。
- 安装脚本 `npm ci`，在新工作区安装依赖。
- 启动脚本，启动容器内的 Redis，并等待服务就绪。
- 「运行测试」「检查类型」「启动开发服务」三个手动操作。
- 保存后点击「测试环境」，查看安装、启动和指定验证命令的结果。

下次选择这个环境时，无需再次粘贴变量或让 agent 猜测如何准备项目。同一个仓库可以另存「集成测试」等环境，并选一个作为默认。

| 本 PR 必须交付 | 用户能做什么 |
| --- | --- |
| 多套可复用环境 | 按仓库创建、命名、编辑、复制、删除环境；设置仓库默认环境 |
| 普通变量与 Secret | 添加、替换、删除；选择安装期、运行期或两者可用；批量导入 `.env` |
| 个人全局变量 | 多个仓库复用；环境内同名配置覆盖全局配置 |
| 安装脚本 | 新工作区自动安装依赖；根据锁文件获取脚本建议；查看输出和失败原因 |
| 启动脚本 | 新容器准备完成及停止后重新启动时，启动所需服务并检查就绪 |
| 已有会话更新 | 显式更新运行期变量，从下一轮生效，保留安装输入与原生会话 |
| 启动失败恢复 | 默认阻止；明确点击后只跳过下次提交的一轮启动 |
| 测试环境 | 在独立临时容器中验证配置，实时看日志、取消、重试；不启动 coding agent |
| 快捷操作 | 保存有名称的命令，在当前工作区手动运行、停止、再次运行并查看输出 |
| 新建任务选择 | 选择环境，查看将使用的变量名和脚本；允许这次任务覆盖变量 |
| 版本与历史 | 查看修改记录、恢复历史版本；明确当前工作区实际使用的版本 |
| 完整运行链路 | 后端、host、终端、前端、脱敏、发布检查、文档和测试一起交付 |

这是「环境配置」功能的完整交付范围。它不自动包含无仓库任务、多人协作、用户资源账单或自带 Claude 账号；这些是原始需求清单中的其他独立功能。

## 2. 概念与生效规则

### 2.1 配置、版本与工作区

**环境配置**属于一个 owner 和一个仓库，以不可复用的 `environment_id` 标识。一个仓库可有多套不同名称的环境；不同用户即使选择同一个仓库，也分别拥有自己的环境。

**环境版本**是一次保存后的完整配置：变量定义、安装脚本、启动脚本、验证命令和快捷操作。保存产生新版本，旧版本不可变。每个 owner 另有一份带版本的**全局变量配置**，只存变量，不包含脚本或操作。

**工作区环境绑定**在新任务创建时确定，固定环境版本、全局变量版本及本次覆盖。它属于整个 sandbox group；普通后续消息、重试、goal 续跑、容器停止后启动，以及共享工作区的 Fork，都使用同一个绑定。

修改已保存环境默认只影响之后创建的新工作区。已有工作区可以明确点击“更新运行期变量”，从下一轮及之后新开的终端使用最新运行期快照；安装期输入和脚本保持原样。不会自动把安装期变更混入旧工作区。

| 用户动作 | 配置行为 |
| --- | --- |
| 新建任务，明确选择某个环境 | 固定用户看到并提交的环境版本和全局版本；版本已改变则提示刷新 |
| 新建任务，未指定环境 | 使用仓库默认环境；没有默认时使用平台基础环境及个人全局变量 |
| 明确选择「平台基础环境」 | 不使用仓库环境的变量、脚本和操作；仍显示并使用个人全局变量 |
| 编辑、导入变量、修改脚本或恢复历史 | 生成新版本，现有工作区不变 |
| 在现有会话点击「使用最新配置新建任务」 | 进入新建任务界面，创建独立工作区；不搬迁原生会话状态 |
| Fork 到相同工作区 | 继承绑定，不允许选择另一套环境或另传变量 |
| 删除环境 | 从新任务选择中移除；已有工作区、历史和必要密文引用保留 |

同名变量按「个人全局 → 所选环境 → 本次任务覆盖」解析，后者覆盖前者的**整条定义**，包括值、类型和可用阶段；再按阶段筛选。比如环境内把同名变量设为“仅安装期”，运行期不会重新露出全局值。

### 2.2 生命周期

| 配置项 | 运行时机 | 可用变量 | 成功条件 |
| --- | --- | --- | --- |
| 安装脚本 | 每个新工作区首次准备；同一容器重启不重复 | 安装期变量 | 退出码为 0；默认超时 900 秒 |
| 启动脚本 | 安装完成后首次启动；之后每次容器从停止到运行 | 运行期变量 | 脚本完成服务启动和就绪检查，退出码为 0；默认超时 120 秒 |
| 验证命令 | 用户点击测试环境时，在安装和启动成功后 | 运行期变量 | 退出码为 0；默认超时 300 秒；可不填 |
| 快捷操作 | 用户主动点击 | 运行期变量 | 命令退出、用户停止或终端生命周期结束 |
| Agent、工具子进程及终端 | 环境准备成功后 | 运行期变量 | 沿用现有执行机制 |

运行中的容器接收新消息、替换成员 CLI 进程或增加 Fork 成员，不重复执行安装或启动脚本。安装和启动均为空时，沿用现有基础环境。

可用阶段和敏感类型是两个独立属性：普通变量和 Secret 均可选择 `setup`、`runtime` 或 `both`；默认 `both`。仅安装期 Secret 不被平台注入运行期进程；安装代码仍可能把它写入文件，这不是隔离仓库代码的保密保证。

模型、runtime、reasoning effort、skills、MCP 和 goal 仍由任务配置管理。网络规则、镜像和资源规格仍由平台管理。

## 3. 用户体验

### 3.1 四个入口

- **Settings → 环境。** 管理个人全局变量，以及按仓库分组的环境列表。列表展示名称、是否默认、版本、变量数量、最近测试结果和更新时间；支持新建、复制、删除及查看历史。
- **新建任务。** 选定仓库后显示环境选择器，自动选中仓库默认环境。可查看有效变量的名称、来源、类型和阶段，进入环境编辑器，或添加仅这次工作区使用的覆盖；Secret 不回显值。
- **右侧 Environment tab。** 默认展示当前工作区实际绑定的配置、全局版本、临时覆盖的名称、安装/启动状态和快捷操作。显式切到「编辑已保存环境」后保存新版本；绑定版本不同则同时标注，不能把最新配置冒充当前配置。
- **「…」菜单 → 配置环境。** 打开上述 tab。Settings 和 tab 共用编辑组件。

环境选择器区分加载中、已就绪和加载失败；加载失败退出 busy 状态，任务文本及仓库选择仍可操作，提供明确错误和重试。配置未知时不静默漏掉默认环境/全局变量；重试成功后，首次成功加载仍选择仓库默认环境，已有明确选择则保留。

第一次使用时也能在任务提交前完成配置，不要求先启动任务再补变量。选择器提供「管理环境」；直接新建的第一套环境默认成为仓库默认，之后新建不自动替换默认。复制不自动设默认，由用户另行选择。

### 3.2 环境编辑器

从上到下排列：

1. **名称、仓库与版本。** 名称可改；所属仓库创建后不可直接修改。复制时可以选择本人有权限的另一个仓库，并明确提示会复制变量及 Secret 配置；新环境有独立 ID 和版本序列，不与原环境联动。
2. **变量与 Secret。** 表格列名称、类型、来源、可用阶段和值状态。普通变量显示值；Secret 只显示「已设置」及更新时间，不显示首尾片段。可替换、删除；从 Secret 改成普通变量必须重新输入值。全局变量只读展示，提供管理链接和「在此环境覆盖」。
3. **导入 `.env`。** 粘贴后预览新增、覆盖、重复或拒绝的变量名、阶段及原因；默认按 Secret、`both` 预览，逐项可显式改为普通变量。非空且去除首尾空白后不足 8 个字符的值不能作为 Secret 保存，预览标明限制；`DEBUG=1` 等非敏感值须由用户选为普通变量，不自动降低敏感级别。确认后整批保存，不允许跳过错误行后宣称成功。界面不把原始文本写进浏览器持久存储。
4. **安装脚本。** 文本编辑器与「根据仓库建议」按钮。建议基于选定分支的锁文件和项目根目录，例如 `package-lock.json` → `npm ci`、`uv.lock` → `uv sync --frozen`；显示依据，用户采纳后才写入。多包管理器或 monorepo 不擅自选择子项目，不覆盖已有脚本。
5. **启动脚本。** 明确提示“启动需要常驻的服务，等待就绪后退出”；提供后台启动及失败退出的示例，不能把永不返回的前台服务直接当作启动完成。
6. **验证命令。** 可选，用于测试环境中的一次验证，例如 `npm run typecheck`；不自动在每次 agent turn 执行。
7. **快捷操作。** 名称、命令、相对工作目录；可新增、排序、删除。示例为运行测试、检查类型、启动开发服务，不要求先有端口预览。
8. **测试与保存。** 「保存」「保存并测试」，有未保存修改时测试先完成保存和版本校验。结果标注环境版本、全局版本、仓库 commit 和镜像 digest；其中任一不同，只展示历史通过记录，不把当前组合标成已验证。
9. **平台环境说明。** 镜像工具链、资源限制、固定网络、安装/启动超时与容器空闲停止策略，只读展示。

变量表显示实际覆盖关系，而不只显示本环境写入的条目。全局 Secret 会进入该用户各仓库的适用执行阶段，保存入口明确说明作用范围。

### 3.3 执行结果与错误

环境准备在会话时间线中展示「安装依赖」「启动服务」两步，提供状态、耗时、退出码和可展开输出，显示最后 64 KiB 的脱敏文本及是否截断。测试环境使用同一套步骤视图，额外显示验证命令。

安装或启动失败、超时都阻止 agent 开始，不降级为警告后继续。可以「重试当前配置」；它仍使用绑定版本。需要修改脚本或变量时，保存后选择新建工作区。失败的安装可能留下部分文件，所以重试提示脚本应可重复运行。

快捷操作显示运行中、已暂停、成功、失败或已停止，并提供打开输出、停止和再次运行。用户切走 tab 不应重复执行；同一运行的重复请求用幂等键合并。已完成或结果未知的运行重试只返回原记录；明确点击再次运行才产生新键。

环境测试失败不禁止用户保存配置或创建任务，但任务仍须通过实际安装和启动。未测试、旧版本测试过、测试失败、已通过是不同状态。

### 3.4 明确的产品限制

- `OPENAI_API_KEY`、`ANTHROPIC_API_KEY` 等平台占用的变量名拒绝保存，并解释原因（§11）；不能宣传“任意 API key 名称都能直接使用”。
- 环境配置不保存正在运行的进程；容器停止后由启动脚本重新拉起服务。容器被删除或丢失后的会话恢复能力仍按现有原生会话设计处理。
- 复制环境复用的是配置，不复制原工作区文件、数据库数据或已安装的容器层。
- 网络仍只允许既定出口，填入远端数据库地址不会放行 5432 等端口；同一容器内本地服务按现有规则使用。

## 4. 数据模型与版本一致性

新增 additive migration，编号以实现时迁移链为准（核对基线最新为 `0060`）。以下为逻辑模型，字段命名应与现有存储约定一致。

| 表或扩展 | 关键字段与职责 |
| --- | --- |
| `agent_environments` | `id` UUID、`user_id`、`repo`、`name`、`revision`、`archived_at`、时间戳；`repo=NULL` 为个人全局变量配置 |
| `agent_environment_versions` | `id`、`environment_id`、单调递增 `revision`、安装/启动/验证脚本、快捷操作定义、修改摘要和时间；发布后不可变 |
| `agent_environment_version_variables` | `version_id`、`name`、`value_ciphertext`、`secret`、`phase`、`value_bytes`；`(version_id, name)` 唯一 |
| `agent_repository_environment_defaults` | `(user_id, repo)` 唯一，指向可用的 `environment_id`，独立 CAS revision；清除默认后退回平台基础环境 |
| `agent_environment_bindings` | owner、repo、固定环境版本 ID、全局版本 ID、加密的本次覆盖、API 安装脚本覆盖、创建时间；不可变，含执行所需的完整版本引用 |
| `agent_threads` | 新增 `environment_binding_id`；origin thread 与同组 Fork 必须指向同一绑定；已有 `setup_script` 保留为解析后的兼容字段 |
| `agent_environment_runs` | 环境测试的绑定、commit、镜像、状态、host、lease/fence、取消标志、步骤结果与脱敏日志引用；独立于 coding job |
| 环境步骤和操作运行记录 | 绑定 ID、sandbox group、容器 boot generation、步骤/操作 ID、run ID、状态、幂等键、退出码、日志及时间 |

全局配置每个 owner 最多一个，其版本禁止脚本和快捷操作。活跃仓库环境的 `(user_id, repo, normalized_name)` 唯一，名称去首尾空格后比较；长度 1–80 字符。删除采用归档，旧 ID 永不复用；之后创建同名环境是新对象。

所有编辑用 `(environment_id, expected_revision)` 做 CAS，而不是只用仓库名或从 0 重置的版本号。删除再创建后，旧页面的写入不能命中新环境。设置默认、删除默认环境、复制、恢复版本均在事务中完成；删除默认环境同时清除默认引用，不自动选另一套。恢复是把旧配置复制成新版本，不改旧版本。恢复过期 token 的配置不等于恢复它在外部服务中的有效性。

### 4.1 新任务绑定

任务创建事务内读取默认选择、所选版本及全局版本，校验权限和合并上限，写入 binding 并关联新工作区。前端提交选择时附所见版本；任意版本发生变化返回 409，列出改变的配置，不静默切换。

API 保留显式 `setup_script` 覆盖：字段未提供时用环境脚本，显式 `null` 或空串表示这次禁用安装脚本；解析使用字段是否出现，不能只判断 truthiness。覆盖和变量一样冻结到绑定上，后续消息接口不接受更换绑定。临时变量默认 Secret，也必须通过保留名和总量校验，不能原样进入普通 job 参数日志。

旧工作区迁移为 `legacy` 绑定，保存它原有的安装脚本和空用户变量，不自动继承后来配置的全局变量，也不在升级后补跑新脚本。旧客户端新建任务时使用当时的默认环境；无配置时维持基础环境行为。功能开启时空配置仍创建绑定，防止以后新增全局变量影响旧任务；空绑定标记 required=False，不阻止 migration downgrade；所有执行入口统一按绑定的 `required` 判断是否需要新协议。空绑定不触发安装、写入冻结、环境 health 检查，不影响运行中打开终端、Fork 或快照，也不要求旧 Sandbox Manager 升级。

### 4.2 合并上限与并发

运行期更新亦受该锁和独立版本 CAS 保护。配置写入和绑定创建在数据库内按 owner 串行化相关检查，例如对 owner 的环境配置锁行使用 `SELECT FOR UPDATE`。改变全局变量时，检查与该 owner 每套活跃环境当前版本合并后的结果；某套超限则拒绝整次写入并返回环境名。改变仓库环境、复制、恢复以及导入时也检查有效集合。

临时覆盖在创建绑定时与指定版本一起校验。不能先分别校验、后并发提交，也不能等到 claim 才发现配置永远无法执行。已经创建的绑定不受后续全局编辑影响。

### 4.3 历史、密文与删除

版本历史展示作者、时间、变量名/类型/阶段的变化及脚本和操作 diff；Secret 的值只显示“新增、替换或删除”。Secret 的当前值、旧值、复制结果均不通过读取 API 返回。

普通变量也加密保存。复用 `AGENT_SOURCE_CONTROL_ENCRYPTION_KEY`，新 domain 为 `hybridinference/environment-variable/v1`，与 MCP/源代码凭据域隔离。无 key 时包含变量的写入和执行返回明确的 503，不保存明文、不跳过变量；不含变量的脚本配置仍可使用。

删除或轮换变量只改变新版本，不删除仍被绑定、原生会话、测试、待发布快照或版本历史引用的旧密文。所有实际注入过工作区的 Secret 版本引用随工作区和发布快照保留，供日志脱敏和发布扫描使用。

活跃环境保留版本历史；归档环境的无引用版本在归档 30 天后可清理。有执行或发布引用的版本不得被级联删除，清理必须先证明引用已释放。临时覆盖随绑定保留，引用释放后清理。备份按既有备份保留策略过期，界面不承诺立即物理擦除。


### 4.4 已有会话的运行期更新与启动恢复

用户点击“更新运行期变量”时，控制面以 owner 权限和 runtime_revision 做 CAS，将当前仓库环境和全局配置按原任务覆盖规则合并，只选择 runtime/both 变量，存为独立加密快照。安装期输入、安装脚本、启动脚本、操作以及原 binding_id 保持不变；不会自动安装新依赖。活动轮次使用已领取的快照，下一轮读取更新后的运行期快照，原生进程的兼容性比较触发进程替换并继续原会话。同组 Fork 共享这次更新；正在运行的服务不会热更新。

原安装 Secret 和先前运行期 Secret 继续参与脱敏与快照检查。运行期旧 Secret 累计最多 512 条、256 KiB；超过时拒绝更新并建议新建工作区。界面展示独立运行期版本及脱敏变量，不暴露历史值。

安装成功而启动失败时默认仍阻止 agent。用户明确点击“本轮跳过启动脚本”，仅授权该 chat 下次提交的一个 human 轮次（含该轮次的重试）绕过启动，不能由兄弟 Fork 或 goal 自动轮次消费。服务可能不可用，界面明确提示。跳过不改变启动脚本、不写 start_done=True；之后的正常轮次仍执行必要的启动。只有已结束的最新轮次可以授权跳过，安装失败不能跳过。

## 5. 校验与上限

变量名匹配 `^[A-Za-z_][A-Za-z0-9_]{0,127}$`，区分大小写。以下保留名在写入时拒绝并说明原因，host 再次校验；发现非法绑定时拒绝运行，不能丢掉冲突项后假装成功。

| 类别 | 保留名字 |
| --- | --- |
| 推理与 Agent CLI | `OPENAI_API_KEY`、`OPENAI_BASE_URL`；`ANTHROPIC_`、`CLAUDE_`、`CODEX_`、`OPENCODE_`、`KILO_`、`PI_` 前缀；`MCP_TOOL_TIMEOUT`、`DISABLE_TELEMETRY`、`DISABLE_AUTOUPDATER`、`DISABLE_ERROR_REPORTING` |
| GitHub 与 Git | `GH_TOKEN`、`GITHUB_TOKEN`、`GH_HOST`、`GH_REPO`、`GH_PROMPT_DISABLED`、`GIT_TERMINAL_PROMPT`、`GIT_CONFIG_NOSYSTEM`；`GIT_CONFIG_` 前缀 |
| 平台自用 | `AGENT_`、`FREEINFERENCE_` 前缀；`WORKSPACE_COMMAND`、`WORKSPACE_CWD` |
| 进程基础 | `HOME`、`PATH`、`USER`、`LOGNAME`、`SHELL`、`PWD`、`TERM`、`BASH_ENV`、`ENV` |
| Docker 客户端 | `chat_sandbox.py` 的 `_DOCKER_CLIENT_ENV`、`_DOCKER_CLIENT_ENV_PREFIXES`，以及代理变量（不区分大小写） |

Docker 客户端名单包含 `DOCKER_`、`BUILDKIT_`、`BUILDX_`、`COMPOSE_`、`LD_`、`OTEL_`、`XDG_` 等前缀。相关集合移到 `cloud_agent_shared` 共用，避免控制面接受而 host 改用含值 argv 或改变 Docker 客户端行为。

| 对象 | 上限与规则 |
| --- | --- |
| 单个值 | UTF-8、无 NUL、最多 32 KiB；允许多行和空值 |
| 单份全局或环境配置 | 最多 100 个变量 |
| 本次任务覆盖 | 最多 50 个变量，单值使用相同上限 |
| 合并有效集合 | 最多 150 个变量；按 `name=value` 加终止字节计，合计最多 128 KiB；所有阶段的并集也须满足 |
| 单段脚本/操作命令 | 最多 8000 字符，无 NUL |
| 快捷操作 | 每个环境最多 20 个，操作 ID 稳定，名称 1–80 字符；工作目录默认仓库根，只能是工作区内相对路径 |
| `.env` 请求 | 最大 1 MiB；重复名、语法错误、保留名、超限均阻止整批导入 |
| 环境测试 | 每个 owner 最多 1 个非终态测试，排队也计入；开始执行后整次最多 30 分钟，超时触发清理 |

这些是产品及协议上限，不声称等于 Linux `ARG_MAX`。部署验收还要在加入平台凭据和 runtime 基础变量后实测可执行性，避免仅按用户字节数估算。

非空 Secret 去除首尾空白后至少 8 个字符，在新增、替换、全局合并及任务覆盖进入持久化前校验；拒绝信息只含变量名和限制，不含值。普通变量不受此最小长度限制。`.env` 预览保留默认 Secret 分类并提示短值，用户可明确把非敏感值改为普通变量后确认。空 Secret 不作为匹配串。脱敏器仍保护收到的完整历史值，不以“短值不打码”绕过已知凭据保护。脚本编辑器提示使用变量引用，不把凭据硬编码进脚本或命令；脚本文本本身不是 Secret 字段。

`/v1/agent/config` 公布保留规则版本、大小上限、各执行超时和支持能力；前后端使用同一份约束。

## 6. Owner API

以下均为拟新增或扩展的主 API 路由，采用 `require_agent_owner`，响应 `Cache-Control: no-store`。每次按 ID 读取、编辑、复制、设默认、恢复和执行都校验 owner；仓库权限沿用任务 admission 的 entitlement 检查。默认选择不能引用他人的或其他仓库的环境。

| 路由 | 作用 |
| --- | --- |
| `GET /v1/agent/environments?repo=` | 列出活跃环境；可按仓库过滤，返回默认标识、revision 和测试摘要 |
| `POST /v1/agent/environments` | 创建具名仓库环境，返回 ID 和初始版本 |
| `GET/PATCH/DELETE /v1/agent/environments/{id}` | 读取、带 CAS 保存整份编辑、归档；PATCH 中 Secret 可保持、替换或删除，不能用遮罩串当值 |
| `GET/PATCH /v1/agent/environment-globals` | 读取或修改个人全局变量及 revision |
| `PUT/DELETE /v1/agent/environment-default?repo=` | 带 CAS 设置或清除该仓库默认环境 |
| `POST /v1/agent/environments/{id}/copy` | 复制到本人指定仓库和名称；不复制测试成功状态 |
| `GET /v1/agent/environments/{id}/versions` | 分页读取历史及不含 Secret 值的 diff |
| `POST /v1/agent/environments/{id}/restore` | 将指定历史版本恢复为新版本 |
| `POST /v1/agent/environment-import/preview` | 指定全局或环境 ID，解析 `.env`，只返回变量名及处理结果 |
| `POST /v1/agent/environment-import` | 携带目标 ID、所见版本及原始文本，重新校验后原子导入 |
| `POST /v1/agent/environment-script-suggestions` | 给定有权限的 repo/ref，读取锁文件并返回建议；不执行仓库脚本 |
| `POST /v1/agent/environment-runs` | 固定环境和全局版本、repo/ref，创建独立测试 |
| `GET /v1/agent/environment-runs/{id}` | 测试状态、步骤与有界脱敏输出 |
| `POST /v1/agent/environment-runs/{id}/cancel` | 幂等取消测试并触发清理 |
| `GET /v1/agent/jobs/{job_id}/thread/environment` | 读取实际绑定配置、来源和准备结果；另返回是否有新版本 |
| `POST /v1/agent/jobs/{job_id}/thread/environment/retry` | 重试当前绑定的失败准备步骤；不更换版本、不重复提交 agent 消息 |
| `POST /v1/agent/jobs/{job_id}/thread/environment/actions/{action_id}/runs` | 在当前工作区执行绑定版本中的操作，返回运行/终端 ID |
| `GET /v1/agent/environment-action-runs/{id}` | 操作状态、退出码、有界输出摘要与终端链接 |
| `POST /v1/agent/environment-action-runs/{id}/stop` | 幂等停止该操作的进程树 |

全局变量同样提供版本读取与恢复能力，分别置于 `environment-globals/versions` 和 `environment-globals/restore`。全局版本恢复须通过所有活跃环境的合并校验。

任务创建扩展 `environment_id`、所见环境/全局 revision 和 `environment_overrides`。`environment_id` 未提供表示选默认，显式 `null` 表示平台基础环境。响应只返回绑定引用及脱敏摘要，不回显覆盖的 Secret。

导入请求增加 `ordinary_names`，只能引用同次导入中的变量；服务端再次解析并校验整批输入，不信任前端的 `secret_allowed` 提示。

所有配置写入明确携带 CAS。409 返回当前 revision 与不含值的冲突说明；复制和执行使用幂等键。测试的取消、超时、完成竞争通过 lease/fence 控制，晚到结果不能覆盖终态。

`.env` 支持 `KEY=VALUE`、可选 `export`、单双引号、注释和空行；引用规则由解析器统一定义，不执行命令替换或变量插值。预览不暂存原始明文，提交时重新解析，并验证目标环境及全局版本未变化。

变量、导入、任务覆盖和 Sandbox Manager 相关错误采用 `CredentialSafeRoute` 等价处理，移除校验错误中的原始 input；422、异常日志、追踪和审计均不记录请求体。Secret 从类型切换、复制、恢复或普通变量读取接口中也不能被间接读出。脱敏路由仅用于接受环境值的输入面（包括创建任务），422 保留字段位置和安全原因，移除原始 input/ctx。普通 jobs 路由保持原校验行为，不把通用 `ValueError` 文本回显给用户。环境加密使用独立 `EnvironmentEncryptionError`，不能全局捕获 `SourceControlError` 后把 GitHub/GitLab/MCP 故障误标为环境加密错误。

## 7. 控制面下发与 host 生命周期

```mermaid
flowchart LR
    UI[Settings / Environment / 新建任务] --> API[环境配置 API]
    API --> V[(不可变版本与密文)]
    V --> B[新工作区或测试绑定固定版本]
    B --> C[校验能力与权限后解密下发]
    C --> H[Host 环境准备协调器]
    H --> I[安装脚本：安装期变量]
    I --> S[启动脚本：运行期变量]
    S --> R[Agent / 终端 / 操作 / 验证命令]
    R --> D[有状态脱敏后上传日志]
```

### 7.1 统一协议与能力门控

`cloud_agent_shared` 增加环境协议与 `ENVIRONMENT_CAPABILITY = "environment-v1"`。该能力表示完整支持绑定版本、阶段变量、准备流程、测试和操作，不是只识别一个 env 字段。

claim 返回固定 `binding_id`、版本引用、解析后的脚本/操作和分阶段变量；所有带值字段 `repr=False`，不得参与普通事件序列化。每次 claim 解密同一安装绑定和显式选择的运行期快照；未点击更新时不读取最新配置。终端、一次性命令、快捷操作、测试和容器启动请求也通过同一解析服务获取绑定。

能力必须验证到实际执行的 runner 和 Sandbox Manager。claim attestation 与 Sandbox Manager 协议握手都需声明支持，且与当前部署/进程代次关联；不能只相信 host 曾注册过新版本。Sandbox Manager 重启后重新协商。对新协议请求禁止忽略未知关键字段。

需要该能力而领取副本不支持时，归还 claim、短暂退避，不消耗任务重试预算，不缺变量继续运行。调度优先过滤不兼容 host，界面显示“等待支持环境配置的 host”。终端和操作等不走 claim 的入口直接返回可重试的能力错误，不发送会被旧 Sandbox Manager 静默忽略的字段。

解密失败按环境不可用处理，显示明确状态并记录无值健康信息；有界退避，不持续占据执行槽位。无新增配置的 legacy 工作区可走已有协议，不要求因空字段整体停用旧 host。

注册、heartbeat 和 claim attestation 均只有在实际 ContainerBackend 和 shared-live/Sandbox Manager 支持完整时才宣告环境能力；运行过程中失去支持后撤销宣告。

### 7.2 准备步骤与恢复

由 host 的 group supervisor 统一协调准备；agent claim、终端、测试或操作进入时都须经过同一 ready gate，不能绕过安装和启动。顺序为：容器建立 → 现有网络校验 → 初次安装 → 启动服务 → 可用。

- 安装成功记录以 `binding_id + 实际容器/工作区身份` 标识；只有确认成功才能跳过。失败或执行结果不明时，不记成功，重试可能再次执行脚本。
- 启动以 `binding_id + 实际容器 ID + boot generation` 标识。同一个容器的每次启动递增代次；host 进程重启但容器未重启时不重复启动服务。
- group 内并发进入通过单个有 fencing 的准备操作合并；准备中不允许另一个请求同时执行安装、启动或 agent。
- 启动失败时清理本次启动创建的受管进程，保留失败输出；重试仅重跑启动。安装失败则重跑安装，成功后再启动。
- 脚本必须可重复运行：平台防止正常路径重复调用，但 host 崩溃与外部副作用之间不存在通用的 exactly-once 保证。
- 不提供从工作区归档重放 transcript 或重建原生会话的新恢复机制；容器丢失继续按既有会话不可恢复规则处理。

安装默认使用仓库根目录和 sandbox 准备身份。安装期创建的后台进程在交接运行期前终止，避免仅安装期 Secret 留在常驻子进程中；缓存和虚拟环境应放工作区可访问的位置。不能假定准备用户 HOME 下安装的工具自动出现在各 member 的私有 HOME/PATH 中。

启动服务使用受管的 sandbox 身份和进程登记，生命周期属于 group，不属于某个 member CLI。成员退出或原生 resume 不应杀掉服务；停止/删除容器时清理。它们只有运行期用户变量，没有成员推理 grant、MCP 凭据或 `GH_TOKEN`，并纳入现有共享写入者快照冻结。

启动脚本需要在超时内启动服务、等待就绪并返回；后台服务输出继续接入有界、脱敏的日志通道。启动脚本成功只证明当时就绪，不承诺通用服务自动重启或持续健康检查。

安装/启动/验证和操作的工具 HOME 使用持久、可执行、组可读写的 /workspace/.cloud-agent-tools/home；工具数据目录通过 UV_PYTHON_INSTALL_DIR、CARGO_HOME、GOPATH、POETRY_VIRTUALENVS_IN_PROJECT 等统一到工作区，成员进程得到同样的工具路径。工具目录加入 Git 本地 exclude，不发布依赖缓存。成员 HOME 仍私有并隔离平台凭据；状态文件和 PID 记录继续放在独立 noexec 私有 tmpfs。前景脚本退出必须强制读取回执，不能采用包装器的 0 退出码；包装器也传播真实失败。服务输出在前景完成后只排空，不再修改或 fsync 准备回执。

### 7.3 注入、终端和成员隔离

`ResidentLaunch`、Sandbox Manager 的 `SharedResidentLaunchConfig` 及终端请求携带绑定身份和对应阶段的环境，纳入兼容性检查；比较绑定/版本标识，不把 Secret 明文或无盐摘要写进日志。平台凭据继续按原机制续期，与用户配置冻结分开。

合并顺序为 backend `base_env()` → 该阶段用户变量 → 平台 HOME/PATH/Git 等 → runtime 凭据与配置。平台与用户名字冲突在前后两侧均拒绝；最终顺序只是防御，不是静默覆盖的产品行为。

使用 `docker exec --env KEY` 按名称传值，由 Docker 客户端环境传递；值不进入 argv、不写容器 create 配置或平台生成的工作区文件。明文仅在授权控制面/host 的内存、进程环境和受保护内部请求中存在。请求、异常 repr、profiling 和持久化 host 状态不得包含值。

Agent 成员沿用独立 UID 和私有目录；不得把平台推理/MCP/GitHub 凭据移入 group 的基础环境。该功能只支持同 owner 的共享工作区，不能借此把个人 Secret 分享给另一用户。

交互终端和一次性命令均使用工作区绑定的运行期变量，冷启动时先通过 ready gate。现有终端不会因保存配置而改值。新增字段必须在 Sandbox Manager 确实消费后才返回成功，不能靠 Pydantic 默认忽略额外字段。配置非空时，控制面在同一次操作前检查实际认证 Sandbox Manager 能力，再发送一次 terminal 请求；Sandbox Manager 在取得终端操作令牌前完成 ready gate。不再先从控制面单独 prepare，再在终端入口重复 prepare；不缓存跨升级失效的能力检查。

## 8. 测试环境与快捷操作

### 8.1 环境测试

测试使用独立的 `environment_run`，有自己的队列、lease/fence、取消和终态；复用 host 容量、沙箱和网络实现，但不伪造一个带空 prompt 的 coding job。

1. owner 选择已保存环境和 ref；默认使用仓库默认分支。幂等重试先按 owner、选择和 ref 查找原 run，不重新读取分支；首次请求控制面解析成确定 commit 并固定环境/全局版本；界面显示这些引用。
2. 获取独立执行槽位，创建临时容器，使用与正式任务相同的镜像选择、资源限制、网络和环境准备路径。
3. 源代码由可信路径获取，不把长期 Git 凭据交给脚本；测试不领取推理 grant、MCP relay 凭据或具有仓库写权限的 `GH_TOKEN`，不启动 coding agent、不发布 PR。
4. 依次执行安装、启动和可选验证命令。验证期间启动的后台服务保持可用；没有验证命令时只证明安装及启动成功，不宣称项目测试已通过。
5. 完成、失败、超时或取消均终止进程并删除临时容器/网络/工作区；保留脱敏结果和版本引用。host 失联由 reaper 标记异常，过期租约不再占用槽位，但保留 cleanup 未完成的孤儿记录；重连 host 在确认清理前不能领取新任务，autoscaler 不把它算作可用容量。领取前失败通过无需解密的 fenced 更新标记失败和清理完成，短暂密钥故障不会遗留运行租约。

测试不能覆盖已有聊天工作区，也不生成可复用镜像。明确显示它仍会运行用户脚本，可能对外部服务产生副作用；本功能只隔离本地工作区，不模拟外部 API。失败重试创建新的 run ID 和干净容器。

并发限制与容量扣减必须包含测试，不能作为绕过 host 资源上限的入口。每台 host 的一个后台执行器负责测试领取、运行及清理；一次在途领取/执行占一个本地槽位，并遵守数据库总容量。主领取循环继续处理 coding task，测试不阻塞剩余槽位。领取最频繁每 5 秒一次，孤儿查询最频繁每 60 秒一次；`/orphans` 只读，租约过期和归档 GC 由已有控制面 reaper 统一执行。关闭 host 时取消后台执行并清理，失联由租约和孤儿回收兜底。浏览器关闭不自动遗留无限运行的测试：显式取消、步骤超时和总 TTL 都由服务端执行。

### 8.2 快捷操作

操作是当前绑定中的具名命令，通过现有 terminal/Sandbox Manager 执行，不创建模型 turn、不使用推理额度。配置更新后，旧工作区仍显示旧操作列表；用户可手动在终端运行其他命令。

操作复用现有终端的 admission、暂停/恢复及 activity 机制：agent 或快照需要协调工作区时，操作进程同样受控，界面显示暂停状态；不能作为绕过共享写入冻结的新通道。新增执行与 snapshot capture 必须串行协调，已运行的进程及脱离原进程组的子进程也在写入者登记/冻结范围内。

运行请求只提交 `action_id`、binding 和幂等键，host 从受信配置解析命令，不信任客户端覆盖 owner、工作区或脚本文本。工作目录必须规范化并检查 realpath 位于工作区内。运行终态保存退出码；停止只终止本次操作进程树，不终止兄弟成员或整组服务。

数据库 run 身份与幂等键持久化，终态不可被迟到的 running 响应覆盖。Sandbox Manager 在产生副作用前，将运行身份写入 host 私有持久目录 `environment-actions`（不挂入容器），完成时保存有界脱敏输出及退出码；terminal 回收不删除这些不含凭据明文的执行记录。相同 run ID 在回收或 Sandbox Manager 重启后也不重新 spawn。停止先于延迟启动请求到达时，保留停止记录阻止该运行随后启动。

状态查询优先读活动 terminal，回收后读取持久结果。若结果缺失或启动完成与否无法确认，标记 `unknown`，明确提示核对外部副作用后手动创建新 run；不能凭 404 判为成功，也不能永远保持 running 或自动重跑。停止遇到 terminal 404 仍完成状态收敛。持久记录由 host 私有状态卷保存；灾难性卷丢失后的结果为未知，不能承诺外部服务的 exactly-once 效果。

允许前台长时间运行命令，沿用交互终端的空闲/断连生命周期和显式停止；输出或实际输入计入 activity，被动查看不无限续命。启动脚本里的服务用于自动随容器恢复，快捷操作用于手动触发，两者分别展示。

操作实时输出使用 owner 授权的终端通道。写入平台历史的输出摘要必须脱敏；停止、运行失败及状态查询也不能回显 Secret。

## 9. 脱敏、历史 Secret 与发布检查

可信快照扫描使用与快照捕获一致的临时 Git index：从固定 base `read-tree`，再 `git add -A -N`，扫描其中新增/修改的实际文件字节；包括未跟踪且未忽略的文件、二进制和符号链接目标文本，不跟随符号链接，不改动用户 index。扫描与捕获处于同一个共享写入冻结边界。受信 publisher 另外扫描暂存 blob，形成独立检查；不能因为发布层会拦截而允许明文 Secret 进入平台快照。

### 9.1 有状态的输出脱敏

Secret 集合来自实际绑定及该工作区曾注入的版本引用，包含安装期 Secret 和临时覆盖。轮换、删除或归档环境不能让旧值失去保护。

脱敏发生在原始文本被上传、持久化或进入异常详情之前，覆盖 runner、Sandbox Manager、环境测试、安装/启动后台输出、操作摘要、资源测量中的文本详情和 snapshot/publish 失败路径。不能只在 `ControlPlane._post` 对每个独立 payload 做 `.replace()`：一个 Secret 可能被分成多个 delta。

共享脱敏器按输出流维护状态，保留最长匹配串所需的尾部缓冲，处理跨 chunk、UTF-8 字节边界及 stdout/stderr 各自的顺序。采用增量输出时，同一逻辑流的截断、拼接、重试、flush、异常和取消都必须遵守它；不能先截断/落盘再打码，或在 cancel 时直接上传未检查尾部。

完整值参与精确匹配；多行值额外匹配去除首尾空白后不少于 8 个字符的实质行，排除 PEM 等通用 `-----...-----` 头尾。单个短行（如 `1`）及通用分隔行不能成为全局匹配串。规则用于日志、可信快照及发布检查，优先最长匹配，替换成 `[secret:NAME]`。空值不匹配。该策略不承诺识别所有任意截断、编码或拆分片段；完整值和符合规则的实质行仍受保护。对日志事件中的指定文本字段处理，不任意改写 ID、digest、序列号、状态或协议控制字段。

在极短输出仍可能是 Secret 前缀时允许暂缓展示；流结束后必须完整检查剩余内容。日志截断作用于已脱敏输出，并保留独立的截断标记。需要累积展示的字段以同一个逻辑流校验，不把单次 HTTP 请求当作秘密边界。

保护目标是已知 Secret 的原文及上述多行表示；不声称能识别编码、变形、逐字符跨不相关事件或由模型改写的所有泄漏。owner 实时终端和文件查看仍是原始内容，只在需要保存摘要时进入脱敏通道。

### 9.2 发布和快照

受信 publisher 读取发布来源工作区的 Secret 版本引用，对应用补丁后新增/修改的待提交文件内容扫描，包含二进制文件字节；命中则阻止发布，仅返回变量名和文件路径。不能仅扫描 diff 文本，也不能只读取用户当前配置，否则拆行、二进制和轮换后的旧值会漏过。

仅删除含 Secret 的旧行不应被误判为新泄漏。后台 snapshot capture 在补丁写入普通存储前执行同类检查；发现 Secret 时阻止该次快照保存并提供脱敏原因，不把原始补丁塞进错误日志。已经排队的发布继续保留其所需历史密文引用。

这不等于任意文件加密或防外发：agent 写到工作区的文件和原始归档仍可能含值；沙箱使用 `GH_TOKEN` 直接 push 不经过受信 publisher；模型上下文也不等同于平台 UI 日志。

## 10. 安全边界与风险接受

用户自带凭据进入沙箱，是本功能需要在同一个实现 PR 中评审并写入安全文档的设计变化：

> owner 主动提供的变量可被其仓库代码、依赖和 agent 读取。提示注入或不可信代码可能使值经现有公网出口外发、进入模型上下文，或被写入文件。平台不承诺阻止这些行为。

平台提供静态加密、owner 授权、Secret 不回显、分阶段注入、已知值的日志脱敏和受信发布扫描；不把这些措施描述为对恶意仓库或模型的保密边界。运维持有解密 key 时仍可解密，与既有凭据存储模型相同。

平台长期账号/服务凭据继续留在沙箱外；用户不能通过环境覆盖平台 grant、MCP、GitHub、宿主 Docker 或网络配置。MCP-only listener、每成员平台凭据隔离、Kata/non-root/capability/seccomp 和资源限制不变。

实现 PR 同步更新 AGENTS.md §7，明确平台凭据与用户主动注入凭据的区别，并更新沙盒安全模型及统一公网出口设计的凭据描述。该例外随同一个实现 PR 写入 AGENTS.md 与安全文档，仍需在 PR 评审中确认。

## 11. 平台推理变量的限制

当前 runtime 适配器用 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY` 等标准名字保存平台推理 grant，用相关 base URL 指向网关，工具子进程还可能继承它们。直接允许同名用户变量会改变 agent 认证，或让用户应用读到错误的凭据。

本 PR 因此保留 §5 的拒绝规则，在变量输入时解释冲突。应用能够自行选择变量名时可使用其他名字；依赖必须读取这些标准名字的应用，在本范围内不能通过同名环境变量配置。不能悄悄覆盖后宣称支持。

本设计不改五种 runtime 的认证体系，也不包含用用户自己的 key 为 coding agent 付费。解除保留名需要验证每个适配器能将平台凭据与用户程序环境分开，是独立的认证设计，不是本功能漏交付的阶段。

## 12. 明确不在本 PR 的范围

| 不包含 | 边界 |
| --- | --- |
| 安装结果快照、预构建和跨工作区依赖缓存 | 本功能复用配置；每个新工作区实际执行安装，不暗示已有 Cursor 式预构建 |
| 仓库内自动发现并执行环境配置文件 | 仅执行 owner 在平台保存或明确提交的脚本，避免仓库更新偷偷改变执行内容 |
| 清理脚本 | 由平台统一管理容器、测试及受管进程清理；本 PR 不提供用户 cleanup hook |
| 网络白名单/模式/代理配置 | 继续使用既有固定网络边界；环境页只读说明 |
| 自定义镜像、Dockerfile 与资源档位 | 沿用平台镜像和调度限制，不新增镜像构建及资源购买流程 |
| macOS/Windows 脚本分支 | 当前云端沙箱为 Linux，不复制本地 worktree 的多系统选择器 |
| 团队共享环境、跨 owner 共享容器 | 个人环境只归属于个人；已有同 owner Fork 保持原义 |
| 无仓库任务、端口预览、用户资源总览 | 独立功能；快捷操作不以这些能力为前提 |
| 文件型 Secret 挂载、任意秘密保险库 | 本次提供环境变量；代码自行落盘仍有 §10 的风险 |
| 解除推理保留名、用户自己的 agent 账号 | 按 §11 的认证边界处理 |

这里是本功能的边界，不是把 §1 已承诺的启动脚本、测试、操作、临时变量或历史移到后续。

## 13. 单个 PR 的实现与合入要求

环境配置是默认提供的产品功能，不设置管理员功能开关。/config 始终提供 environment_limits，Settings、任务环境选择和 Environment tab 始终显示，不依赖额外配置请求成功才出现。旧数据库或部署残留的 repository_environments_enabled=false / AGENT_REPOSITORY_ENVIRONMENTS_ENABLED=false 不再影响功能。用户没有配置变量或脚本时，任务使用基础环境，不执行环境准备；已有工作区继续使用固定绑定。权限、加密、runner 与 Sandbox Manager 的 environment-v1 能力检查继续生效。

Environment tab 的 GET 不写库，Secret 脱敏材料按 owner、绑定、运行期版本和加密 key 缓存 60 秒，最多 256 条；状态的 Docker inspect 在线程执行器运行并缓存 15 秒。准备摘要由实时 attempt 租约锁保护的生命周期事件写入，不能由失去租约的 host 覆盖。操作状态轮询不重复查询 GitHub entitlement；新操作仍校验权限。过期检查持续执行，历史 GC 每小时一次，反向引用查询配套索引。

环境列表初次加载失败时仍可提交，省略环境字段，由服务器应用默认环境和全局变量，并显示回退说明。发布遇到环境解密故障按暂时不可用重试，不永久失败。


同一 PR 内可以按依赖顺序开发和组织 commits，但须完整包含以下内容，不能只合入 API 或占位 UI：

1. 共享协议、保留规则、版本/绑定存储、owner API 和迁移。
2. admission 固定配置、Fork 继承、claim 和所有 Sandbox Manager 入口的能力检查。
3. 安装/启动协调器、变量注入、终端、环境测试、快捷操作和清理。
4. 流式脱敏、历史 Secret 引用、快照及发布扫描。
5. Settings、Environment tab、「…」入口、新建任务选择/覆盖、导入、历史和完整运行状态。
6. 安全文档、运维说明、中英文文案及下面的验收测试。

兼容滚动部署是这个 PR 自身的要求：迁移先可用，host/Sandbox Manager 宣告能力后才承接新增配置。部署期间不能丢变量执行，测试队列也不能把新协议派给旧进程。

首次创建新绑定前，所有接收任务创建、后续消息、Fork 和终端请求的控制面副本必须已升级；不能让旧副本将新绑定视为无配置。存在新绑定后不支持直接回退到不理解绑定的旧二进制。回滚须先关闭相关执行入口、排空测试及准备操作，并保持已绑定工作区由兼容版本服务或处于禁止执行状态；部署检查和运维说明必须落实这一限制。

删除当前 `setup_script` 描述中已失效的缓存承诺，修正 `runner.py` 的遗留 `cached=False` 展示；不引入新的 setup cache。完整实现合入时再更新 `docs/README.md` 已实现设计索引。

## 14. 验收标准与验证

### 14.1 用户可见验收

| 场景 | 必须成立的结果 |
| --- | --- |
| 首次配置 | 在新任务执行前创建环境、添加变量和脚本、保存并选择，无需把 Secret 放进 prompt |
| 同仓库两套环境 | 可分别命名、复制、设默认；新工作区按选择运行，各自不互相覆盖 |
| 全局与环境重名 | 明确显示来源和覆盖结果；阶段覆盖不会意外回退到全局值 |
| 一次性覆盖 | 只影响该新工作区及同组 Fork，不改已保存环境；后续 turn/终端保持一致 |
| `.env` 导入 | 预览可理解、错误明确；全部成功或全部不写入；无 Secret 回显 |
| 安装与启动 | 初次顺序执行，普通消息不重跑；容器停止再启动只重跑启动；失败阻止 agent |
| 测试环境 | 有步骤日志、取消和重试；不调用模型，不改已有工作区，结束后资源被清理 |
| 快捷操作 | 可运行测试或开发服务、查看状态、停止和再运行；无端口预览也能用 |
| 保存新版本 | 当前工作区仍使用旧版本，界面标明差异；新建工作区可选新版本 |
| 历史与删除 | 可恢复成新版本；删除环境不破坏既有工作区，也不让旧 Secret 失去脱敏保护 |
| 错误与限制 | 保留名、超限、权限、旧 host、失效测试状态均有具体提示，不静默退化 |

### 14.2 后端与数据库验证

- 所有 owner API 的越权、仓库 entitlement、Secret 类型转换、复制/恢复及错误响应测试；请求日志和 422 不含测试 Secret。
- 加密 domain 隔离、无 key 行为、版本不可变、归档引用和 GC；删除再建同名对象后旧 CAS 失败。
- 并发全局/环境写入、导入、设默认和绑定创建的数据库测试，证明有效上限不会因竞态突破。
- 显式 `setup_script` 的未提供/null/空串语义；临时覆盖加密及继承；同组 Fork 不能更换绑定。
- 普通消息、重试、goal、终端和测试均使用正确固定版本；轮换后旧会话默认仍读旧值；点击更新后只更换运行期值，安装输入保持原样，新工作区读完整新版本。
- 不兼容 runner、Sandbox Manager 重启后协议退回、旧 Sandbox Manager 忽略额外字段等情形均拒绝执行；任务重试预算不因能力不匹配消耗。
- 环境测试的并发额度、lease 过期、取消/完成竞争、TTL、host 失联及孤儿清理；不给予推理/MCP/Git 写凭据。

### 14.3 Host、输出与发布验证

- 安装/运行阶段过滤，合并顺序，Docker argv 无值，`docker inspect` 无用户变量；进程中用哈希比较验证值而不打印真实值。
- 并发 ready 请求只启动一次；host 进程重启不当作容器 boot；停止后重启执行启动；失败、取消和模糊完成可安全重试。
- 安装期后台进程被清理，group 服务不随 member 替换而死；服务、操作和 detached 子进程均受快照冻结约束。
- 终端、一次性命令、快捷操作冷启动不绕过准备；操作幂等、暂停恢复、相对路径与 symlink 逃逸、停止范围正确；覆盖完成后/回收后/进程重启后的同键重试，以及状态查询和停止的 404、模糊启动与迟到结果。
- Secret 在任意 chunk 边界切分、UTF-8、多行、相互包含、短值、flush、取消、截断和日志重试时都验证；覆盖 runner 与 Sandbox Manager 的所有持久化输出路径。
- 轮换/删除后的旧 Secret 仍被识别；未跟踪/已暂存/已跟踪文件、二进制、符号链接目标文本、分行补丁和待发布快照扫描有效；删除秘密内容不被误阻止，错误不含值。
- 五个 runtime 在真实 host 各验证普通变量读取、平台凭据不受覆盖、native resume 与 Fork 行为；多租户边界在 Kata 下验收。

### 14.4 前端与质量门禁

覆盖任务选择器、编辑/绑定视图差异、版本冲突、全局覆盖、导入原子性、Secret 不回显、测试状态失效、操作及错误/取消状态；环境加载失败仍可切换仓库，重试保留默认选择，导入短值须显式分类。用真实 API 完成“创建 → 测试 → 新建任务 → 修改版本 → 新任务复用 → 删除”的用户流程。

实现 PR 合入前运行 `make check`、Node.js 22 下的 `make ci-frontend`，以及依赖 Postgres 的 `make test-db`；对生命周期和隔离要求执行对应 host/Kata 验收。缺失真实环境验证须在 PR 中明确列出，不能用 mock 通过替代声明全部验收完成。
