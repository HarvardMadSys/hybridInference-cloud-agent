## 1. 交付目标

所有任务使用同一套网络实现。准备环境、安装依赖和 Agent 执行期间，都能访问公网以运行 curl、Python HTTP 客户端、pip、npm 和 Git over HTTPS。

用户和运维都不选择网络模式。删除 `platform_only`、`trusted`、`custom`、`full` 及其选择逻辑；不再新增 `public_web` 枚举、模式字段或启用开关。公网访问是完成安全初始化后的标准能力。

准备与执行仍是任务流程中的两个阶段，但不再决定网桥、代理、DNS 或防火墙策略。Fork 沿用同一组的网络与工作区，成员进程和短期凭据仍各自隔离。

网络保护未就绪时拒绝执行任务；运行中发现保护失效时停止执行并断开该组网络。这是故障处理，不提供降级后的另一种可运行网络模式。

## 2. 固定边界

| 类别 | 统一规则 |
|---|---|
| 公网出口 | 允许普通公网 IPv4 单播地址的 TCP 80/443 |
| DNS | 仅允许平台指定解析器的 TCP/UDP 53 |
| 平台调用 | 平台为 Agent 配置的推理、MCP 地址使用本组两个固定中继；网关公网入口的可达性及 grant 重放按 §3 处理 |
| 受保护目标 | 拒绝宿主所有地址、私网、链路本地与云元数据、CGNAT、组播、保留等非普通公网地址、其他沙盒组和部署方追加的网段；DNS 与中继只有上述精确例外 |
| 其他传输 | 拒绝其他公网端口、UDP 443/QUIC，以及经沙盒网卡收发的 IPv6；沙盒自身的本地环回服务不属于公网出口 |
| 入站 | 不发布沙盒服务端口，不接受外部主动建立的连接；回包必须属于获准的出站连接 |
| 凭据 | 平台持有的长期平台、源代码托管和 MCP 上游凭据不进沙盒；沙盒继续持有各自受限的短期推理令牌和 MCP 令牌 |

边界按实际数据包执行，不依赖 Agent 自觉遵守，也不依赖程序使用某一种 HTTP 客户端。

- TCP 80/443 是端口约束，不保证其中一定是 HTTP；本期不检查 HTTPS 内容，也不承诺阻止 DoH 或这些端口上的应用层隧道。
- 沙盒可以把仓库内容和短期令牌发往公网，本设计不承诺防外发。第三方服务的认证权限仍由其凭据决定。
- 控制面、网关的公网地址可能可达；MCP 工具路径不在主 API 上提供，推理 grant 的公网重放风险按 §3 接受。不承诺所有平台公网地址在网络层不可连接。

## 3. MCP 入口前提与推理 grant 风险接受

**MCP 工具调用仅由 MCP 专用应用提供。** [#327](https://github.com/HarvardMadSys/hybridInference-cloud-agent/pull/327) 已合并，部署还要确认中继最终连接到该应用（容器内默认 8001），而非主 API。主 API 保留连接管理、OAuth 回调和工具审批，不挂载工具调用 router。这项前提继续成立。

**2026-09-25 决策：接受推理 grant 外传及公网重放风险。** 项目选择保留现有授权与中继实现：grant 仍由网关签发，进入成员的 CLI 进程环境或私有临时配置；推理中继仍连接网关现有推理入口（host Compose 默认远端端口 8080）。不要求 hybridInference 增加独立内部入口，也不增加宿主机代持 grant 的替身中继。

本决定适用于真实用户的发布，不再把“公网拒绝 inference grant”作为上线前提。接受的风险与范围是：

- 仓库、依赖、网页或其他内容可能促使任务代码取得并外传本成员的 grant；持有者可通过可达的网关推理入口重放它。本决定接受这种未经用户同意的使用，不以“仓库由用户选择”证明凭证不会泄露。
- 重放仍归属 grant 对应用户，只能调用其被允许的模型，受该用户现有配额、有效期和撤销检查约束。它消耗用户额度及平台推理资源；没有新增任务预算或固定损失金额上限，也不授予其他用户身份、MCP 工具或平台管理权限。
- grant 的短 TTL 不是从泄露时起算的固定窗口。驻留进程有效期间心跳会续期，一次 turn 结束不撤销 residency grant；默认 30 分钟空闲回收也不是所有活动情况下的绝对上限。停止、替换、接管和释放继续执行现有撤销流程，撤销失败时由剩余 TTL 兜底。
- 成员凭据隔离、平台长期密钥不进沙盒、MCP 入口隔离、模型权限和配额检查、租约与撤销、Kata 及网络隔离要求继续保留。本决定不扩大 grant 权限，不放宽这些实现或测试。

该决定替代本节原有的独立推理入口前提及其跨仓库切换方案。FreeInference 对 v4 部署格式的适配仍然需要；推理入口切换与宿主机代持凭证都不再是它的发布依赖。

Owner 主动配置的个人环境凭据是单独的产品输入，允许进入其沙盒，并接受经
现有公网出口外发、进入模型上下文或被代码写入文件的风险；详见
[环境设计](2026-10-12-repository-environment-design.zh-CN.md) §9–§10。
该例外不增加出口、代理、网络模式或跨 owner 访问，不允许覆盖平台凭据名字。

## 4. 唯一网络拓扑与配置

```text
沙盒组（准备、执行、Fork 共用）
  └─ 本组网桥
       ├─ 推理中继 ──SSH──> 网关现有推理入口
       ├─ MCP 中继 ──SSH──> MCP 专用应用
       └─ 宿主防火墙、路由与 NAT ──> 公网 IPv4 TCP 80/443
```

每个活跃组使用一张可路由网桥，从本部署地址池分配 /29。沙盒只连接本组网桥；组内只包含该沙盒和受信的两个中继。网络按组及 generation 归属管理，保留创建、恢复核验和释放逻辑。

公开多租户执行仍要求 Kata、非 root 用户、移除 capabilities、seccomp 和资源限制。runc 仅用于受信仓库的开发测试，不因统一网络实现而放宽运行时隔离。

两个中继仍可使用受信服务发现网络，但沙盒不得加入它。该网络只用于发现固定服务，不作为另一档沙盒出口。删除 setup/agent 各自的网桥和代理发现网络。

保留部署所必需的参数，不提供策略选择：

| 参数 | 用途 |
|---|---|
| `AGENT_SANDBOX_NAMESPACE` | 标识本部署的资源与防火墙表归属 |
| `AGENT_EGRESS_CHAT_NETWORK_POOL` | 本部署组网桥的 IPv4 地址池；部署时显式配置 |
| `AGENT_EGRESS_DNS_SERVER`（新增） | 一个固定 IPv4 解析器地址；仅授权 TCP/UDP 53 |
| `AGENT_EGRESS_PROTECTED_CIDRS`（新增） | 追加受保护网段，包括使用公网地址的实验室内网；只能增加保护范围 |
| 现有推理、MCP 中继配置 | 固定服务的发现、连接与隧道目标，不授权任意目的地 |

同一宿主上的部署地址池必须互不重叠，也不得与宿主已有网络冲突。检查其他部署配置的完整地址池，不能只比较已经分配出去的 /29。安装时登记归属并串行校验分配，避免两个部署同时启动而漏检。

## 5. 宿主执行边界

规则由受信宿主组件管理，沙盒不获得宿主 `NET_ADMIN`、Docker socket 或通用特权执行通道。

1. **范围限定。** 使用本部署独立表；按本部署网桥接口及其合法源地址识别流量。异常源地址拒绝。IPv6 也按接口归属拦截，不能靠 IPv4 源地址池匹配 IPv6。禁止全局 flush、修改其他部署规则或切换 Docker 防火墙后端。
2. **访问宿主。** INPUT 覆盖宿主所有本机地址，包括网桥网关、公网地址和其他接口。若指定 DNS 服务位于宿主，仅放行其精确地址与 53 端口。
3. **经宿主转发。** FORWARD 检查实际目的地址，拒绝受保护目标，仅放行 §2 的出口。Docker 端口映射须覆盖 DNAT 后真实目的地址，不能通过宿主发布端口进入受保护服务。
4. **桥内通信。** 中继按所属组、实际地址和服务端口放行，其他端口拒绝。中继挂接、替换和移除时原子更新相应集合；一个组的例外不得变成访问其他组的授权。确认桥内流量实际经过的钩子，必要时使用 bridge family 执行限制。
5. **回包与撤销。** 只接受对应获准出站连接的回包；不放行外部主动入站。更新保护集合或停用组网络必须约束已有连接，不得被无条件的 `ct state established accept` 绕过。
6. **规则生命周期。** 规则先安装，再连接和启动不可信工作负载；更新使用原子事务。runner 进程退出不能清掉仍在保护沙盒的规则。宿主重启时先恢复保护，再恢复任务。
7. **失败行为。** 可安全返回明确拒绝的连接应立即报错；规则缺失或校验失败就停止执行、断开对应组网络，不退回旧代理或无约束直连。日志记录组、失败环节和原因，不记录令牌或请求正文。

固定规则加少量接口、地址与端口集合就是执行状态；不新增策略快照表、用户授权策略、每目的地租约或续租服务。

## 6. DNS 与任务生命周期

DNS 使用指定解析器。runc 的开发测试路径通过 Docker DNS 配置；Kata 由受信 helper 写入 guest 的 `/etc/resolv.conf`，同时保留中继 `/etc/hosts` 条目同步。helper 使用平台固定代码，校验目标文件的归属和写权限，不能让仓库提供待执行命令或任意写入路径。

任务执行顺序：

1. 宿主完成规则安装、地址池校验和运行时验证，才接受任务。
2. 创建组网桥、挂接中继、安装对应集合与 DNS，启动受信的沙盒初始化过程。
3. 从实际 guest 核对网络、规则、DNS、中继及受控探针；通过后才运行仓库代码或依赖安装脚本。
4. 准备完成后直接执行 Agent，沿用同一网络。删除仅为切换出口而进行的网桥替换、代理变量切换和 Kata 停机重启。
5. 恢复或复用沙盒、中继替换、Docker/宿主重启及规则重装后，重新核验实际边界；失败则停止执行并断开组网络，保留工作区。
6. 组释放时移除本组连接与集合，再清理网桥。原有执行租约、凭据刷新、驻留回收和成员进程清理继续履行各自职责。

完整安全验收使用正在监听的受控目标及允许路径的正向对照。日常启动检查覆盖实际拓扑和关键探针，不扫描真实内网，也不读取云元数据凭据。超时、目标未监听或证据不足不得记为策略阻断成功。

## 8. 开发测试环境清理与交付

本次不存在正式用户的旧网络兼容需求，不设计灰度、双模式运行、旧任务自动迁移或旧模式回退命令。

实现完成后，在确认过归属的开发测试环境执行一次性清理：停止该环境旧 runner 与沙盒，移除旧代理、旧组网桥、旧配置和旧网络记录，再使用统一版本的控制面、runner、镜像与前端重新创建测试任务。保留所需工作区，不能借此删除其他部署的资源或无关数据。

一次性清理工具若需要识别旧标签，只用于这次离线清理，不进入新服务的运行路径。新服务不采用或修复旧拓扑；遇到遗留资源应报告清理要求。

独立验证环境用于安全验收，不构成另一种网络模式。测试机若同时承载其他服务，仍须保证地址池、接口及规则归属隔离。验收失败时保持服务不可执行并修复；不切回某个旧 tier 继续运行。

## 9. 实施与验收

交付顺序允许拆 PR 便于审查，但最终版本不得同时携带旧模式和新模式，也不依靠 feature flag 隐藏旧实现。

| 顺序 | 工作 | 完成标志 |
|---|---|---|
| 1 | 确认 MCP 入口隔离及 §3 的推理 grant 风险接受 | MCP 主 API 无工具路径；现有推理中继可用，用户绑定、模型权限、配额及撤销检查保留 |
| 2 | 在独立 Kata 环境走产品路径验证最小拓扑 | guest 自动路由、DNS、两个中继和宿主阻断均有真实流量证据 |
| 3 | 完整替换网络实现，同时完成 §7 清理 | 统一网桥、规则、DNS、生命周期、配置、API、前端、部署及测试闭环；没有旧模式分支 |
| 4 | 清理并重建开发测试环境，完成下表验收与质量门 | 新版本按唯一规则运行；结果可复现，未运行项不得冒充通过 |

推理 grant 风险接受只移除独立推理入口的发布依赖；MCP 入口、Kata 验收、部署清理及其他现行发布条件继续保留。完整 Git 历史仍单独处理，本次不修改 Git 获取策略。

| 验收类别 | 通过标准 |
|---|---|
| 公网能力 | 实际 Kata 中 curl、Python HTTPS 证书校验、HTTP 80、包下载、Git HTTPS 可用 |
| 端口与 DNS | 其他公网 TCP 端口、UDP 443、其他解析器的 TCP/UDP 53 被拒；指定解析器正常 |
| 地址分类 | 私网、链路本地/元数据、CGNAT、组播、保留地址及追加保护网段被拒；DNS 重绑定或重定向后的实际私网连接也被拒 |
| 宿主与映射 | 宿主各类地址上的受控监听服务、网桥网关、Docker 发布端口均不能绕过保护 |
| 组与部署隔离 | 另一组监听服务不可达；冲突地址池被拒；两个部署并行时不会修改或误伤彼此规则 |
| 中继 | 本组两个中继的服务端口可用，其他端口被拒；替换中继后例外及时更新 |
| IPv6 与入站 | 沙盒网卡的 IPv6 被拒；外部不能主动连入沙盒；获准出站连接的回包正常 |
| 不可信代码权限 | 沙盒成员不能修改路由、防火墙、受管 DNS 或宿主规则，也不能自行取得 helper 权限 |
| 执行顺序 | 规则、DNS 和自检完成前，仓库代码与安装脚本不执行；准备到执行沿用同一网桥与规则，无网络阶段切换 |
| 生命周期 | 恢复复用、中继替换、Docker/宿主重启后边界不变；故障停止执行、断开出口且保留工作区；组释放无残留 |
| 已有连接 | 改为受保护目标或停止组网络后，持续收发的连接确实停止；未受影响的对照继续通信 |
| 凭据入口 | MCP 令牌在主 API 找不到工具路径；推理 grant 的用户绑定、模型权限、配额、有效期与撤销检查保留；审批与撤销回归通过。推理 grant 的公网重放按 §3 接受，不作为必须拒绝的断言 |
| 删除完整性 | 活跃代码、API、前端、Compose、镜像清单和 CI 不再支持旧 tier、旧代理或旧网络切换；仅历史说明或明确的删除检查允许出现旧名称 |

拒绝项必须有可达的受控目标作对照；使用随机测试数据，不发送仓库文件或真实凭据。复用双向持续流量探针，并通过有意移除一条限制来证明测试能够发现放行漏洞。

运行 `make check`、本次涉及的前端/制品检查及必要数据库测试；真实网络结论由独立 Kata 验收提供。普通 Docker 结果不能替代 Kata 证据。

## 10. 不在本次范围

用户或运维可选网络模式、域名白名单产品、每组网关容器、注入 guest 路由、网络租约、策略快照、完整出站审计、滥用监控、IPv6 出口支持、浏览器服务与公网预览均不实现。

旧实验材料只允许按需要复用地址分类器、双向流量探针和反例测试方法。受保护地址集合属于基础设施隔离规则，不是重新引入任务级域名白名单。
