# Measurement 默认可控制，采集默认 Disabled

日期：2026-09-22。目标：修正 #318 的部署默认值，复用已有 Admin 开关。

## 用户行为

正常部署并完成数据库迁移后，管理员直接打开 **Admin → Measurements**：

- 没有活动实验时，显示 **Disabled** 和 **Enable measurement**。
- 点击 Enable，选择操作和 host 后，才开始选取匹配操作。持续采集直到 Disable，不再要求选择时长。
- 点击 Disable，停止选取新操作；在途测量正常完成，历史样本保留。
- 关闭页面不改变开关；服务重启读取持久化状态，不会创建新实验。已有定时实验仍按原期限停止。

使用开关不需要设置 profiling 环境变量，也不需要重启或部署。Enabled 后必须实际执行
沙盒启动、文件访问或终端操作才有样本，开关不会主动制造业务操作。

## 问题与决策

原默认把两件事合成了一个状态：没有配置 `MODE` 时，既不采集，也不允许 Admin 控制。
因此页面虽然部署成功，却显示 Unavailable，管理员看不到按钮。

现在区分**控制方式**和**采集状态**：默认控制方式是 Admin；初始持久化状态没有活动实验，
所以采集仍然 Disabled。不是把 profiling 默认打开，也不是由前端伪造一个可点击按钮。

CP、runner、broker、turn 子进程都通过共享模块的 `profile_mode()` 解析相同默认值。
Compose 已将空值透传给该函数，空串与未设置必须行为一致。无需新增表、API、状态机或配置
分发协议；迁移 0018 已提供初始关闭的控制状态。

## 兼容与可选运维覆盖

| 输入 | 控制方式 | 结果 |
| --- | --- | --- |
| 不设置 `MODE`，或空白；旧 `ENABLED` 未设置或为 false | Admin | 开关可用，没有活动实验就不采集 |
| 不设置 `MODE`，旧 `ENABLED=true` | Environment | 保留主动配置的旧静态实验；仍须有合法 RUN |
| 显式 `MODE=admin` | Admin | 忽略旧 ENABLED/RUN，以持久化实验为准 |
| 显式 `MODE=environment` | Environment | 仅使用静态实验配置 |
| 显式 `MODE=disabled`，或无效 MODE | 禁止采集 | Admin 不可启用；也拒绝在途 context；无效值告警 |

保留覆盖项是为了已有静态实验和运维禁用，不是普通使用的前置条件。已经部署的
`MODE=admin` 无需删除；不再推荐新部署为显示按钮而增加该变量。

`AGENT_OPERATION_PROFILING_DEPLOYMENT` 仍是可选的数据库命名空间：一个数据库对应一个
部署时使用默认值即可；多个独立部署共享数据库时必须用不同名称。它不控制采集开关。

## 进程与边界

- CP 从数据库读取配置，runner 经已有认证端点同步，broker 接收 runner 的配置。
- 新根操作只从当前有效快照选取。无活动实验、未获取策略或策略不合法，都不创建测量。
- 默认模式下，子进程及 broker 可以延续可信通道传来的合法选择；不要求它们先自行选中
  实验。仍校验原 manifest、操作范围和截止时间，不占第二份名额。
- 显式部署级 `disabled` 继续拒绝接续，与 Admin 上的 Disable 保持区别。
- 权限不变：Admin 写接口仍需管理员身份；runner 与 broker 仍走既有认证通道。
- 数据库不可用或迁移缺失时不伪造 Disabled，接口继续报告真实错误。

## 关闭时成本

没有活动实验时，业务入口不创建 measurement、span、导出记录，也不为每次操作访问 DB。
为接收按钮的变化，已有后台配置同步会运行：空闲约 30 秒一次，活动约 5 秒一次，错误重试
约 10 秒。按钮状态表示持久化配置，不表示所有节点同时生效；持续模式的断联节点要等同步恢复才会收到 Disable；已有定时实验仍受到期时间约束。
本改动不声称关闭后零后台 I/O。持续模式没有累计样本上限，导出队列仍有容量限制。
持续采集的协议、迁移和验证见 [后续设计](2026-09-22-continuous-admin-measurement.zh-CN.md)。

## 验证与发布

1. 未设置、空串、空白 MODE，以及旧 ENABLED=false：Admin 可控但无新测量。
2. 真实 Admin 路由在无 profiling 配置时返回 `configured=true / status=off`，Enable、
   Disable、权限拒绝仍有效。
3. 真实新解释器不设置 MODE 也能接续父进程选择；显式 disabled 拒绝同一选择。
4. 真实 Postgres + HTTP 验收链清除 MODE 和 deployment 配置：初始关闭 → Enable →
   CP/runner/broker 同步 → 样本落库 → Disable → 新操作不采集，在途记录仍可入库。
   broker 的文件执行用测试替身，不能据此声称真实容器性能已验收。
5. 运行仓库 `make check`，保持静态实验、过期边界和明确禁用的回归断言。

发布只需常规升级四类进程到包含本改动的版本，沿用标准数据库迁移；不需要新增运行配置。
混合版本期间旧 producer 仍遵循旧默认，完整行为需升级完成。首次部署没有活动实验；已有
数据库中未到期、未停用的 Admin 实验仍会恢复，这是持久化开关的正常行为。回滚应用默认值
会恢复原先的环境配置要求，不删除实验或样本。
